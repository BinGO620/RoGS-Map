## 4. 候选修正案（三个，**分级启动**；按 R7 预算设计，**未派发**）

### 候选 0（**改首选**）：crowd 族**可判性**（测量功率；**近零实装**——仅 ① 重渲染）
- **动机更正（`verdict_L1.md` §8 C1 之后）**：原候选 1 的前提——"护栏恢复三件套交付"——**已作废**：
  **crowd2 两臂本就能渲染成功（4 帧，off 1.4657 / exit 0.1378）**，交付能力从未丢失（且"护栏后 rc=0"
  这一判据**现状即满足 ⇒ 天然无判别力**，二轮审查已点名）。真正的问题是**判别力**：Δ−1.33cm < 同码噪声 2.33cm。
- **内容**（按成本升序）：① 渲染帧集 4 → 与运行期同构（`render_compare --vacated-window-frames` 出 **freshvac 口径**）；
  ② 给 crowd 族补**运行期 freshvac 列**（当前 CSV 只有 32 列、static 段整段缺失）——**注：② 属运行期代码改动
  （非"零实装"）**，若采纳须按例外流程登记（修正案 → 提交 → 快筛）；
  ③ 同码重跑再加 1–2 seed，拆解 2.33cm 噪声的来源（渲染抽样 vs 训练随机性）。
- **判据（跑前锁定，**有判别力**，含失败分支）**：
  - **成功分支**：同码噪声地板降到 **< 1.19cm**（判据阈值）**并给出 crowd2 的明确判定**（|Δ| > 1.19cm，正负皆可）；
  - **失败分支**：若 2.33 → <1.19cm **不可达**（例如噪声主因是训练随机性而非渲染抽样） ⇒ **终态结论 =
    "crowd 族在本仪器/本帧数下不可判"**，资源转向 A（**这也算可交付的边界结论，不是失败**）。
  - **可达性估计（先验，待实测）**：噪声可拆为"渲染抽样"与"训练随机性"两部分；若渲染抽样占优，
    扩帧集（4→与运行期同构）预计可显著降低；**训练随机性占优则大概率走失败分支**。
- **成本**：0–0.5 天 + **2 run**（只补渲染则近乎零训练成本）。
- **① 已执行（2026-09-20，零训练，<1 分钟）**：结果见 `crowd_judgeability_2026-09-20.md` ——
  **4 帧口径 Δ−1.71cm / 噪声 3.03cm（不可判）→ 17 帧密帧口径 Δ−2.01cm / 噪声 0.96cm（可判）**，
  两口径方向一致（机制使残影更小）；**帧集事后选择 + 同码噪声仅 1 对 ⇒ 诊断级，须预注册后方可主张**。
  ⇒ **候选 0 的"可判性"目标已达成**；**③（第三同码 run 出 sd）亦已完成**：
  `prereg_crowd_judgeability.md` + `prereg_amendment_1_crowd_judgeability_instrument.md` → `crowd_judgeability_confirm.md`
  （3 对 Δ 全负、mean **−3.74cm**、噪声 1.52cm ⇒ **PASS，诊断级**）。②（运行期 freshvac 列）仍留待 L3 预注册决定是否实装。

### 候选 1（**降级**为"前置取证项"）：基元尺度护栏 `alpha_scale_guard`
- **前提（零 GPU 取证）**：巨基元的**族别与分布尚未取证**（§8 C2 撤回了 58–65 个 / 25.6m / 194 个）
  ⇒ 先对**三族两臂 PLY** 做尺度直方图 + "尺度 × 不透明度"联合分布，确认**哪一族**存在会撞栅格化上限的退化基元。
- **若取证成立**：在 `_alpha_lifecycle_step` 的 prune 段加**对称**护栏（任一轴 > `guard_max_scale_m` 者
  钳制或剔除并计数，入 `backend_timing.json`，零活动臂也有一列）。
- **判据**：护栏未改变 mvnobox/balloon2 的 freshvac 读数（|Δ| ≤ 1.19cm，对称两臂）；
  crowd 族的读数改善**只在候选 0 使其可判之后**才有资格谈。
- **成本**：取证 0 天（零 GPU）；实装 0.5 天 + 2 run（**仅在取证成立后**）。

### 候选 2（次选，机制向）：carve 证据的跨 KF 聚合（治 H1）
- **内容**：`min_obs_count` 3→5 或改共视聚合（BDGS 式）；**同时**加 reset-only 臂做对照（治 H2）。
- **预期**：crowd2 的 carve 速率从 0.42/step 提升到可用水平；若无效 ⇒ 判定"拥挤场景不满足本机制的
  证据前提"（**这本身是有价值的边界结论**，回答用户"方法不完整"= 机制适用域的真实边界）。
- **判据**：crowd2 freshvac 配对 Δ 为负且 |Δ| > 1.19cm（与 L1 同判据），ATE ≤ +0.5cm；否则止损。
- **成本**：实装 1 天 + **4 run**（crowd2 {off, exit, exit_aggregate, exit_reset_only}，1 seed）。
- **退出规则**：R2 —— 本族（exit/carve 拥挤域）**只允许一次**修正案快筛；失败 ⇒ 拥挤域永久关闭，
  作为边界写进论文（`DISCIPLINE.md` R7：击杀只补 1–2 seed）。

### 预算与派发（分级）
**候选 0**（可判性）= 2 run / 近乎零训练成本，**近零实装**（仅 ① 用现有 PLY 重渲染；**② 若采纳属运行期改动**，见上候选 0 注）⇒ 无论 D2 选什么，它都是 crowd 族的**前置**；
**候选 1**（尺度护栏）= 取证 0 GPU + 条件成立后 2 run；**候选 2**（证据聚合）= 实装 1 天 + 4 run。
全链（0→1→2）上限 **8 run ≈ 4–5 小时 GPU**，仍远低于 D2 的"单批 ≥3 GPU-天"升级阈值；
